## Why these datasets

There is no public, labelled set of Indian retail receipts that we could find. SROIE and CORD are the
standard public receipt-understanding benchmarks with openly downloadable labels. They differ from the
target domain in ways that matter, and the results should be read with that in mind:

- **Merchants:** SROIE companies are Malaysian ("... SDN BHD"). Our parser prefers merchants from an
  Indian lexicon and otherwise takes the first name-like header line. SROIE headers often start with a
  person's name, "COPY" or a logo, so merchant accuracy is expected to be low.
- **Amounts:** CORD writes `60.000` for sixty thousand rupiah. Our amount rules expect Indian formats
  (`60,000.00`), so CORD totals are mostly misread. This is a known domain gap, not tuned away.
- **Dates:** SROIE dates are day-first like Indian ones, so this field transfers best.

The parser was frozen (parser v1.1, commit `dc4fc2f`) before any real-data run and was **not** tuned
on these test splits.

## Using your own data

The loaders in `experiments/datasets.py` yield records with this shape; any labelled receipt set that
can be mapped to it can be evaluated with a new config:

```python
{"id": str, "image": bytes, "source": str,
 "fields": {"merchant": str|None, "date": str|None, "total": str|None, "address": str|None, "n_items": int|None},
 "gt_lines": list[str] | None}
```

A small labelled set of real Indian bills (even 100 receipts) would be the most valuable addition.
Dataset required before evaluation.
