# Deploying SpendLens

Target setup: **frontend on Vercel**, **API on Render (Docker)**, **database on MongoDB Atlas**.
Each piece is free-tier compatible. Nothing here is deployed automatically from this repo; the
owner creates the accounts and connects the GitHub repository.

```text
browser ──HTTPS──> Vercel (static React build)
                     └─ /api/*  rewrite ──> Render: spendlens-api (FastAPI in Docker) ──> MongoDB Atlas
```

The frontend calls relative `/api/...` URLs (same as local development, where Vite proxies them).
On Vercel, `frontend/vercel.json` rewrites `/api/*` to the Render service, so the browser only talks
to one origin and no CORS preflight is needed. No `localhost` URL is used in production.

## 1. MongoDB Atlas

1. Create a free M0 cluster.
2. Database Access → add a user with a generated password.
3. Network Access → allow `0.0.0.0/0` (Render free instances have no fixed outbound IP).
4. Copy the `mongodb+srv://...` connection string. The app creates its collections and indexes
   in the `spendlens` database on first start.

## 2. Backend on Render

1. New → Blueprint → select this repository. Render reads `render.yaml`
   (service `spendlens-api`, Docker, root directory `backend`, health check `/api/health`).
2. Fill in the variables marked `sync: false`:

| Variable | Required | Value |
|---|---|---|
| `MONGO_URI` | yes | Atlas connection string |
| `CORS_ORIGINS` | yes | your Vercel URL, e.g. `https://spendlens.vercel.app` (only needed for direct API calls; the rewrite makes browser calls same-origin) |
| `JWT_SECRET` | yes | generated by Render (`generateValue`). With `ENV=production` the API refuses to start if it is missing or shorter than 32 characters |
| `ENV` | yes | `production` (set in `render.yaml`) |
| `MONGO_DB` | yes | `spendlens` (set in `render.yaml`) |

The image installs `tesseract-ocr` + English data with apt, so OCR works without any extra Render setting. `ADMIN_EMAILS` is optional (only listed users may retrain the category model).

3. Deploy, then open `https://<service>.onrender.com/api/health`. It must report the database
   as connected and the model as loaded.
4. If Render gives the service a different hostname than `spendlens-api.onrender.com`, update the
   destination in `frontend/vercel.json` and commit.

Free Render instances sleep after ~15 minutes idle; the first request after that takes roughly a
minute while the container starts. Memory measured locally with `docker run --memory 512m`
(the free-tier limit) on 2026-09-16: ~190–250 MB (peak during a scan) after startup and a real request.

Seeding demo data is optional: from a machine that can reach Atlas, run
`MONGO_URI=... MONGO_DB=spendlens python -m scripts.seed` in `backend/` (PowerShell:
`$env:MONGO_URI="..."; $env:MONGO_DB="spendlens"; python -m scripts.seed`).

## 3. Frontend on Vercel

1. New Project → import this repository → **Root Directory: `frontend`**.
2. Vercel detects Vite; `vercel.json` sets `npm run build` and output `dist`. No environment
   variables are needed.
3. Deploy and open the URL. Sign up, then run the main workflow once to confirm the rewrite
   reaches the API.

## Checking a deployment

```bash
curl https://<vercel-app>/api/health      # goes through the rewrite
curl https://spendlens-api.onrender.com/api/health
```

## Building the API image yourself

```bash
cd backend
docker build -t spendlens-api .
docker run --rm -p 8000:8000 -e MONGO_URI=... -e JWT_SECRET=... spendlens-api
```
